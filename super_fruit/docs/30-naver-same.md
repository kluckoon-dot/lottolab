# 30 · 네이버 키워드도구와 같게 (2026-10-16)

보갬: "우리는 엔부 키워드가 없고 아이템스카우트와 네이버 광고 키워드 도구에는 모두 나와. 내가 원하는 건 네이버 키워드 광고와 동일하게 키워드랩에 구현하는 거야. 왜 차이가 있는지 확인해 보자." → "모든 키워드들이 완벽하게 네이버 키워드 도구와 일치해야 해!"

## 왜 달랐나

엔부는 수집돼 있었다(9월 전체 수집 · 네이버 연관 목록 9곳). 화면에 올리는 단계에서 빠졌다.

| # | 원인 | 크기 |
|---|---|---|
| 1 | 화면 명단을 **섹션 글자 규칙**(sections.json)으로만 골랐다. 키워드 글자에 품목 이름이 있어야 들어갔다. 화면의 분류기(catMake)와 규칙이 서로 달라, 분류기는 신선식품으로 읽는데 명단에서 빠진 것이 많았다 — 쭈꾸미(월 10만) · 장어 · 전어 · 홍어 · 맛있는쌀 | 네이버 목록에 나오는데 화면에 없던 키워드 56,208개 |
| 2 | 글자로는 품목을 못 읽는 키워드(엔부 · 안창살 · 토마호크)는 아예 못 들어갔다. 네이버는 엔부를 사과 목록 9곳에 띄운다 | |
| 3 | 키워드별 네이버 목록을 **잘라서** 실었다 — 씨앗과 품목 · 묶음이 같은 줄만(감홍사과 → 미니오이 · 오이피클을 뺐다). 품목을 못 읽는 씨앗의 목록은 싣지 않았다 | |
| 4 | 연관 목록의 기본 보기가 **같은 품목만**이었다 — 네이버가 준 줄 일부가 숨었다 | |
| 5 | 숫자는 **받은 날 값**이다. 네이버 키워드도구는 최근 30일 값이라 날마다 조금씩 바뀐다(엔부: 10/12 수집 50 · 310 → 10/16 네이버 화면 70 · 370) | |

네이버 자신이 품목이 다른 키워드를 섞어 준다는 것도 확인했다: 사과 목록 672개 안에 여름딸기 · 생딸기 · 방울토마토 · 멜론 · 오이 16개.

## 바꾼 것

### 1. 네이버가 연관으로 준 키워드는 모두 담는다 (build-web.mjs)

받아 둔 네이버 목록(품목 씨앗 · 꼬리 키워드 · 키워드별 목록)에 나온 키워드는 전부 키워드랩에 들어간다. 숫자는 목록에 같이 온 네이버 값이고, 화면에 있던 키워드도 목록 쪽이 더 새것이면 그 값으로 바꾼다.

| 자리 | 무엇 | 어디서 보나 |
|---|---|---|
| 섹션 (data-kw.js · 28,601개) | 글자 규칙 + **네이버 목록에 나온 키워드라면** 화면 분류기가 신선식품으로 읽는 것 | 황금키워드 표 · 시장 지도 · 트렌드 · 검색 |
| 섹션 밖 사전 (data-dict-0~11.js · 125,590개) | 네이버 목록에는 나오지만 다섯 섹션에 안 드는 것 (농협 · 저녁메뉴추천 · 엔부 …) | 정확 키워드 검색 · 연관 목록. 황금키워드 표에는 안 나온다 |

- 분류기를 **목록에 나온 키워드에만** 쓰는 까닭: 9월 전체 수집분에 그대로 쓰면 엔비디아주가 → 사과, 룰루레몬 → 레몬처럼 엉뚱하게 읽힌다. 네이버가 우리 신선식품 씨앗의 연관으로 띄웠다는 것이 먼저 걸러 준다.
- 식품 판정(쇼핑인사이트 식품 분야 클릭 0)으로 빠지는 규칙은 그대로다. 빠진 것도 사전에 남아 찾을 수 있다.
- **네이버 이웃 품목**: 글자로 품목을 못 읽는 키워드는, 그 키워드를 목록에 띄운 씨앗들의 품목이 한 품목으로 모이면(씨앗 5곳 이상 · 80% 이상) 그 품목으로 본다. 엔부 → 사과(9/9). 화면 머리 카드에 "(네이버 연관으로 본 품목)" 이라고 적는다. 섹션에는 넣지 않는다 — 담양죽녹원 · 목포케이블카 · 두드러기 같은 말도 그렇게 모여서다. 품목 칸 · 연관 단계 · 씨앗 고르기에만 쓴다.
  안창살 · 토마호크 · 치마살 · 제비추리 · 척아이롤 · 우족 · 냉삼 · 박하지(꽃게) · 대두(콩) · 호도(호두)처럼 분류표에 없는 진짜 품목 이름이 이 목록에 많이 보인다 — 축산물 정리 때 분류표에 넣는다.

### 2. 키워드별 네이버 목록을 자르지 않는다 (build-related-more.mjs)

네이버가 준 줄 전부, 준 순서 그대로 싣는다. 품목을 못 읽는 씨앗의 목록도 싣는다.

### 3. 연관 목록 기본 = "네이버 그대로" (keyword-lab.html)

그 키워드로 네이버에 물은 목록(받아 둔 것 · PC 실시간)이면 기본 보기는 **네이버 그대로** — 키워드도구 화면과 같은 줄, 같은 순서. 단추로 좁힌다.

| 단추 | 보이는 것 |
|---|---|
| 네이버 그대로 | 네이버가 준 줄 전부 (기본) |
| ○○ 관련만 | 씨앗과 품목이 같은 것 + 꼬리 키워드 |
| ○○까지 | 같은 묶음(과일 · 수산물 …)까지 |
| + 꼬리 키워드 | 네이버 목록 뒤에 꼬리 키워드(품목 이름 + 1kg · 가격 · 국내산 …를 직접 물어 찾은 것)를 붙인 것 |

- 그 키워드로 받은 목록이 없어 품목의 목록으로 대신 보여 줄 때(표시줄에 "품목 ○○ 에 네이버가 준 목록" 이라고 적힌다)는 전처럼 같은 품목만이 기본이다. 대신 보여 주는 목록을 "네이버 그대로" 라고 부르면 틀린 말이 된다.
- 연관 목록을 열 때 품목 칸 거르기(F.cat)도 푼다 — 줄 수가 네이버와 같아야 한다.
- 섹션 밖 줄은 황금키워드 표에 안 낸다(찾거나 목록에서 볼 때만).

### 4. 씨앗을 넓힌다 (fetch-related-more.mjs)

키워드별 목록을 받는 씨앗 = 화면의 신선식품 키워드(검색 100 이상) + 네이버 이웃 품목이 있는 사전 키워드(엔부).

### 5. 정기 수집 순서 (4 정기 수집.bat · 27-related-more.bat)

목록을 다 받은 뒤 build-web.mjs 를 한 번 더 돌려, 새 목록에 나온 키워드와 새 숫자가 바로 화면에 들어가게 했다. 매주 받는 목록이 약 7,500 → 12,600 개로 늘어 정기 수집은 60~120분 걸린다(검색광고 API 만 · HUB 한도 안 씀). 예약 작업이 올리는 파일에 data-dict-N.js 를 더했다.

### 6. 숫자는 가장 새로 받은 줄 (naver-latest.mjs)

같은 키워드라도 받은 날이 다르면 숫자가 다르다. 같은 시각에는 어느 씨앗으로 물어도 같은 숫자가 온다(복숭아사과 · 엔부를 씨앗 4~5개로 동시에 물어 확인).
목록 파일(build-related · build-related-more)이 섹션 밖 키워드의 숫자를 "먼저 만난 목록" 에서 가져와, 엔부가 10/12 값(360)으로 보였다. 이제 받아 둔 목록 전부에서 가장 새 줄을 쓴다(440).

## 숫자는 언제 같은가

네이버 키워드도구의 숫자는 **최근 30일** 값이라 날마다 조금씩 바뀐다. 키워드랩(claude.ai 저장본)은 **받은 날의 네이버 값**이다 — 받은 날에는 같고, 다음 날부터 조금씩 벌어진다. 매주 월요일 정기 수집으로 다시 맞춘다.
PC 에서 "1 키워드랩 열기" 로 열면 찾을 때마다 네이버에 지금 묻는다 — 그때는 지금 값이고 목록도 네이버 그대로다.
