# 18 · 대표 카테고리 · 저장본 구매층 · 겹쳐 보는 차트 · 연관키워드 세 겹 (2026-10-11)

보갬 지적: 사과를 찾았는데 대표 카테고리에 '배' 만 뜬다 · 상세의 발견 경로/왜 ○○/주의/의도 판정은 쓸모없다 ·
그래프는 아이템스카우트처럼 한 그림에 겹쳐야 하고 마우스를 올리면 주간 값이 나와야 한다 · 저장본에 없는 것은 다 받아라 ·
카테고리와 연관키워드가 아이템스카우트에 뒤지면 안 된다.

## 1. 대표 카테고리

**원인.** 화면은 아이템스카우트 엑셀이 준 카테고리(`ICAT`)만 썼다. 엑셀을 넣은 적 있는 '배' 34개 말고는 18,656개가 전부 빈칸이라,
무엇을 찾든 고를 수 있는 칸이 '배' 하나였다.

**네이버는 상품 카테고리를 API 로 주지 않는다.** 아이템스카우트의 값은 그 키워드로 팔리는 상품 목록에서 낸 것이다(쇼핑검색 API 는 7/31 종료, 크롤링은 하지 않는다 — docs/04·08).
그래서 엑셀을 넣은 키워드는 그 값을 그대로 쓰고, 나머지는 키워드 글자에서 읽는다 (`keyword-lab.html` 의 `catMake`):

1. 품목 — 우리말 합성어는 뒤가 머리다. 제일 뒤에서 끝나는 품목 (청송사과 → 사과, 밤고구마 → 고구마). 품목 사전 = `SEEDS` 710개 + 보강 50여 개
2. 품종 — 품목 글자가 없는 품종명은 사전으로 (부사 → 사과, 신고 → 배, 샤인머스캣 → 포도, 살치살 → 쇠고기)
3. 형태 — 품목 뒤에 가공·용도 말이 붙으면 그 칸 (사과즙 → 건강즙/과일즙, 밤묘목 → 묘목/씨앗/재배, 밤양갱 → 젤리/양갱/간식)
4. 한 글자 품목(밤·배·감·귤·쌀·김…)은 가격·10kg·햇·국산·추석·공주 같은 꾸밈말을 떼고 본다 (배추천 = 배 + 추천, 공주햇밤가격 → 밤)

**채점 (같은 날 아이템스카우트 엑셀, 식품 카테고리가 붙은 290개).** 같은 칸 210 · 다른 칸 17 · 글자로 못 읽음 63.
읽은 것 중 93% 가 같다. 못 읽는 63개는 `CJ` · `프리미엄` · `10kg` · `국산` 처럼 품목이 없는 말이고, 아이템스카우트는 여기에
칼슘 · 전복 · 스파게티면 같은 칸을 붙여 놓았다(그 말로 팔리는 상품이 우연히 많은 칸). 이런 것은 비워둔다 — 짐작으로 채우지 않는다.
다른 17개는 보늬밤(통조림) · 꿀밤(가공안주) 같은 가공 브랜드다. **100% 같게는 못 만든다. 엑셀을 넣은 품목만 완전히 같다.**

화면 키워드 18,690개 중 미분류 208개(1.1%). 고르는 칸은 지금 걸린 조건을 통과한 키워드로만 센다 —
사과를 찾으면 사과(294) · 건강즙/과일즙(49) · 주스/음료(25) … 가 나온다.

## 2. 저장본 구매층 (`refresh-buyers.mjs` · 25단계)

저장본(claude.ai 페이지)에는 9월에 받은 2,430개뿐이었다.

- 기기·성별·연령 전용 API 는 키워드 하나씩(키워드당 3회). 대신 클릭 추세 API 를 `device` · `gender` · `ages` 로 걸러 5개씩 받고,
  닻(닭가슴살)을 같이 넣어 `키워드 값 ÷ 닻 값 × 닻의 비중` 으로 낸다. 전용 API 와 소수점까지 같다 (청도반시 모바일 76.8 = 76.8, 여성 54.0 = 54.0). 4개에 10회 → 키워드당 2.5회.
- 요일은 일간 클릭 1년을 요일로 모은다. 5개에 1회.
- **결과: 요일 19,254개(전부) · 기기·성별·연령 6,422개(구매로 이어지는 검색이 큰 순서) → 저장본 합계 7,132개.**
- 나머지 약 12,800개는 3.2만 회가 더 든다. 쇼핑인사이트 한도가 한 달 5만 회라 이번 달에는 못 넣는다(아래 6).
  달이 바뀌면 `수집단계\25-buyers.bat` 을 누르면 이어 받는다. PC 실시간 서버에서는 고르는 키워드마다 바로 받으므로 빈칸이 없다.

## 3. 쇼핑 클릭 추세가 계단으로 보이던 것

사과 클릭량이 계단 모양이었다. 원본은 정밀하다(41.73634 …). **쇼핑인사이트 클릭은 3년 사이 전체가 크게 줄었다** —
사과 · 밤 · 고구마 모두 최근 값이 2023~24년 최고점의 2~5% 다. 한 주를 한 글자(90단계, 자기 3년 최고점 = 89)로 접으니 최근 1년이 2~5칸에 뭉개졌다.
클릭 추세만 한 주 = 두 글자(8,100단계)로 다시 받았다(`trend-fresh.json` 의 `clickChars: 2`, 3,860회). 검색 추세는 그대로 한 글자.

## 4. 종합 차트 · 상세

- 항목마다 따로 쌓던 것을 한 그림에 겹친다. 왼쪽 눈금 = 검색수, 오른쪽 = 클릭량(%). 상품수·경쟁강도는 점마다 값을 적는다. 항목 단추로 켜고 끈다.
- 마우스를 올리면 그 칸의 기간과 값: `2025.10.13~2025.10.19 · 검색수 33,437 · 클릭량(%) 100`. 저장본 주간은 월~일(네이버 주간 단위)이라 아이템스카우트(일~토)와 하루 어긋난다.
- 상세 맨 위에서 발견 경로 · 왜 ○○ · 주의 · 의도 판정을 뺐다. 그 자리에 **작전 보드**:
  타이밍(성수기/상승/비수기 · 피크 달 · 최근 4주 대비 · 작년 대비) / 3위로 한 달 광고하면(예상 클릭 · 광고비 상한 · 본전 주문 · 목표 전환율일 때 손익) / 같은 품목에서 점수 높은 키워드 5개.
  판정 근거는 판정 알약에 마우스를 올리면 나온다. 머리 카드의 "수집 경로" 도 대표 카테고리로 바꿨다.

## 5. 연관키워드 (밤, 같은 날)

네이버 키워드도구는 씨앗 하나에 연관을 125개만 준다. 아이템스카우트 연관 탭은 322개(네이버 · 카카오 · 쿠팡 · 지마켓 · 11번가를 모은 것).
실시간 서버(`live-server.mjs` `lookup`)가 세 겹으로 모은다. 숫자는 전부 네이버가 지금 준 값이다.

| 겹 | 방법 | 밤 |
|---|---|---|
| 1 | 키워드도구 연관 | 125 |
| 2 | 씨앗 글자가 든 연관 상위 40개를 다시 씨앗으로 | +38 |
| 3 | 우리 전체 수집본(56만 개, `all-keywords.tsv`)에서 씨앗 글자가 든 것 상위 100개 + 꼬리말(가격 · 보관법 · 10kg … 71개)을 직접 조회 | +499 |
| | 합 | **662** |

'밤' 글자가 든 키워드로 재면 우리 593 · 아이템스카우트 148 · 겹침 92. 아이템스카우트에만 있는 56개는 밤부베베 · 긴긴밤 · 라로슈포제…밤 같은 식품 아닌 것과
보늬밤 · 밤만쥬 · 찐밤 · 율피밤 같은 것이다. 뒤쪽은 네이버 연관에도 우리 수집본에도 없어 이름을 알 길이 없다 — 엑셀을 `넣는곳\아이템스카우트` 에 넣으면 그 이름으로 네이버 값을 받아 채운다.
처음 찾는 씨앗은 15초쯤 걸리고 3시간 동안 저장된다. 입찰가는 검색량 큰 순 500개까지.

저장본(실시간 아님)에서는 네이버 연관 + 같은 품목 수집분을 한 표에 놓는다. 고른 키워드가 품목 이름이면 그것을 데려온 씨앗의 형제(사과 ← 한라봉)는 섞지 않는다.

## 6. API HUB 쇼핑인사이트 한도 (한 달 5만 회)

10월 추정 사용: 식품 판정·쇼핑 지수 약 1.05만 + 추세 0.39만 + 구매층 2.0만 + 클릭 추세 재수집 0.39만 + 시험·실시간 조회 약 0.3만 ≈ **4.1만**. 남은 것 약 0.9만.
실제 사용량은 NCP 콘솔에서만 볼 수 있다(로그인 필요). 실시간 조회 한 번에 15~20회 쓴다. 이번 달은 큰 수집을 더 돌리지 않는다.
