# 상품수 없이 서는 지표 — 구매의도와 광고경쟁도

2026-10-11. 보갬: "키워드랩은 결국 아이템스카우트를 대체할 만한 플랫폼이 되어야 한다."
상품수는 필요할 때 보갬이 엑셀을 받아 그 품목만 본다. 나머지는 네이버 원본으로 선다.

## 먼저 — 아이템스카우트 데이터를 통째로 받지 않는다

"수집된 모든 키워드에 대해 하루 최대치만큼 받자" 는 하지 않았다.

아이템스카우트 이용약관(2021-08-05 시행)을 직접 읽었다.
- 제10조 ① 1 서비스의 "무단복제 … 모방", 5 "매크로 프로그램 등" 금지
- 제11조 서면경고 → 이용 제한 → 영구 정지
- 제17조 ① 서비스 제공 과정에서 발생하는 데이터·정보·산출물 일체의 권리는 회사에 귀속, ③ 사용권·라이선스 부여 안 함

남의 데이터베이스를 통째로 받아 그 서비스를 대체하는 것은 약관 위반이자 docs/04 의 다윈중개 판례와 같은 그림이다.
게다가 그 숫자는 낡았다(docs/16). 대체하려면 우리 원본이어야 한다.

## 검증 방법 — 아이템스카우트는 베끼는 대상이 아니라 채점표

보갬이 넣어준 엑셀 두 개(밤 · 배 연관키워드) 405개 키워드를 네이버에서 직접 받아,
아이템스카우트가 적어둔 **분류(쇼핑성/정보성)** 와 **상품수** 를 정답지 삼아 네이버 값 중 무엇이 따라가는지 쟀다.

## 구매의도 — 풀렸다

```
구매의도 = (식품 쇼핑 클릭 지수 ÷ 검색수) ÷ (닭가슴살의 같은 값)        닭가슴살 = 1
```

쇼핑성 287 · 정보성 39 를 가르는 힘(AUC. 0.5 = 못 가름, 1 = 완벽):

| 지표 | AUC |
|---|---|
| 검색수 | 0.45 |
| 광고 깊이 · 광고 클릭률 · 클릭수÷검색 | 0.64 ~ 0.66 |
| 입찰가 1위 · 3위 | 0.71 ~ 0.73 |
| **쇼핑 클릭 ÷ 검색수** | **0.86** |

쇼핑성의 중앙값이 2.06, 정보성은 0.000 (75% 지점도 0.002). 못 가른 쇼핑성은 대부분 식품 밖이다
(화장품 "x" · 유아 "밤부베베" · 가전 "밤까는기계" · 패션 "GAP") — 식품 분야 클릭을 재니 0 인 게 맞다.

### 9월에 다섯 번 재고 네 번 실패한 이유 (docs/09)

그때 "쇼핑클릭지수 ÷ 검색량" 은 방향이 뒤집혔다(추석선물세트 0.007 < 콜라비효능 1.150).
쇼핑인사이트는 **한 번에 넣은 키워드들 중 제일 큰 값을 100** 으로 둔 상대값만 준다.
키워드를 하나씩 부르면 저마다 자기 최고점이 100 이 된다. 눈금이 키워드마다 달랐다.

이번엔 호출마다 **닻 키워드를 같이** 넣어 한 눈금으로 만들었다.

닻 = 닭가슴살. 1년 월별 최대÷최소가 1.5배로 제일 안 흔들린다 (쌀 1.9 · 김 2.5 · 계란 2.9 · 밤 22.9).
제철 키워드를 닻으로 쓰면 달마다 눈금이 바뀐다.

### 문턱

식품 쇼핑성 229개의 구매의도 분위: 10% 0.13 · 25% 0.63 · 중앙 1.47 · 75% 2.52

| 문턱 | 식품 쇼핑성을 잘못 버림 | 정보성을 잘못 살림 |
|---|---|---|
| 0.01 | 3% | 13% |
| **0.05** | **6%** | **8%** |
| 0.1 | 8% | 3% |
| 0.2 | 12% | 0% |

0.05 에서 버려지는 쇼핑성은 CJ · 국산 · 친환경 · 특대 · 1개 같은 낱말 조각이고,
살아남는 정보성은 "밤파는곳" · "공주밤판매" — 사실상 구매 키워드다.

```
없음   < 0.05      검색은 되는데 사지 않는다 → 황금점수 0 · 판정 패스
낮음   0.05 ~ 0.3
보통   0.3 ~ 1
높음   ≥ 1         닭가슴살만큼, 또는 그 이상 "검색하면 산다"
```

```
쌀10KG 2.0 · 청도반시 1.3 · 밤 0.86 · 추석선물세트 0.81 · 고수 0.50
장수사과축제 0.024 · 한우자조금 0.017
```

## 수요 — 검색수가 아니라 "구매로 이어지는 검색"

```
수요 = log10(검색수 × 구매의도 ÷ 100) ÷ 2        (0 ~ 1.5)
```

검색은 많은데 사지 않는 키워드(축제 · 협회 · 레시피)가 황금키워드 위로 올라오던 문제가 이걸로 내려간다.
쇼핑 클릭을 아직 모르는 키워드(-1)는 전처럼 검색수로 잰다. 막지 않는다.

## 광고경쟁도 — 상품수의 대용이 아니다

상품수를 맞히는 네이버 지표는 없다. 식품 231개에서 스피어만:

| | 상품수 | 경쟁강도(상품수÷검색) |
|---|---|---|
| 옛 식: 깊이/15 × 0.55 + 1위/2500 × 0.45 | 0.19 | 0.08 |
| **새 식: 깊이/15 × 0.5 + 모바일 3위/2000 × 0.5** | **0.40** | **0.29** |
| 깊이만 | 0.40 | 0.26 |
| 3위만 | 0.39 | 0.33 |

1위 입찰가는 상품수를 거의 안 따라갔다(0.09). 한 사람이 높게 지르면 뛰는 값이라 그렇다. 3위 · 깊이가 낫다.
눈금은 기준선 5.0 이 옛 식과 같은 자리에 오게 골랐다 — 식품 키워드의 90% 가 5.0 아래다(옛 식 91%).
옛 식보다 두 배 낫지만 0.40 이다. **그래서 이름을 그대로 광고경쟁도로 둔다.**
"광고로 들어가는 데 드는 값" 을 재는 지표이고, 상품수 ÷ 검색수(경쟁강도)는 상품수가 있을 때만 따로 보여준다.

## 판정

```
패스    월 검색 < 100  ·  마진율 < 20%  ·  구매의도 < 0.05 (새로)
린정    광고 감당 O  AND  광고경쟁도 ≤ 5.0
반린정  둘 중 하나
```

구매의도 문턱은 `RULE.buyNone` 한 곳에서 바꾼다.

## 수집

`refresh-naver.mjs` 의 식품 판정 단계가 닻과 함께 4개씩 부른다. 한 번에 식품 여부(f)와 쇼핑 클릭 지수(c)가 같이 나온다.
식품 통과 19,288개 → 4,822회. 일주일에 한 번(`--food-age`).
실시간 서버는 검색한 키워드와 연관 상위 60개만 그 자리에서 받는다(15회).

## 저장된 수집본에도 클릭량 — 3년 주간 추세를 다시 받았다 (2026-10-11)

보갬: 종합차트의 "클릭량(%)" 에 줄이 그어져 있다. 이건 수집할 수 없나?

수집할 수 있다. 실시간 서버에서는 고르는 키워드마다 받고 있었고, 저장된 수집본에만 없었다.
`refresh-trend.mjs` 가 화면 키워드(식품 통과 19,296개)의 157주 주간 추세를 한 번에 5개씩 받는다.

```
검색어트렌드  /search-trend/v1/search               검색 추세   19,221개
쇼핑인사이트  /shopping/v1/category/keywords (식품)  클릭 추세   19,260개
4.5분 · 호출 7,720 · 실패 0
```

- 9월 추세는 9/14 에서 끝났고 화면 키워드의 59%(10,939개)만 있었다. 이제 10/4 까지, 18,615개.
- 마지막 주가 덜 차면 곡선 끝이 꺾여 보여서 지난 일요일까지만 받는다.
- 키워드마다 자기 최고점을 100 으로 다시 맞춘다. 9월에는 묶음 안의 큰 키워드에 눌려 작은 키워드의 곡선이 계단처럼 뭉개졌다.
- 눈금은 새로 받은 추세면 지금 검색수에 맞춘다. 9월 추세만 있을 때는 9월 검색수(sepTot)에 맞춘다.
- `2 오늘 값으로 갱신` 에 넣었다. 같은 주 안에서는 이미 받은 것을 건너뛴다(호출 0).

기기 · 성별 · 연령 · 요일 클릭 비율 카드는 아직 저장본에 없다(9월에 받은 2,200개뿐).
키워드 하나에 세 번씩 불러야 해서 전부 받으면 5.6만 회 — 쇼핑인사이트 월 한도(5만)를 넘는다. 실시간 서버에서는 고르는 순간 받는다.
