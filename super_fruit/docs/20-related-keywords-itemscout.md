# 20 · 연관키워드를 아이템스카우트와 같게 (2026-10-11)

보갬: "연관키워드가 아이템스카우트와 동일한, 다르더라도 1~2개 정도 차이나는 것만 인정. 이외에는 동일한 추출값을 표시하도록 완벽 적용. 완전 중요한 포인트."

## 왜 네이버 자료만으로는 같아지지 않는가

같은 날(10/11) 씨앗 `밤` 으로 쟀다.

| | 개수 | 아이템스카우트 330개와 겹침 |
|---|---:|---:|
| 네이버 검색광고 키워드도구 연관 | 125 | 125 (전부 저쪽에 있다) |
| + 한 겹 더 + 우리 수집본 + 꼬리말 조회 (docs/18 §5) | 662 | '밤' 글자가 든 148개 중 92개 |
| 아이템스카우트 연관 탭 | 330 | — |

아이템스카우트에만 있는 것은 세 갈래다.
- 상품명에서 나온 낱말: `x` · `CJ` · `공주` · `대` · `중` · `10kg` · `프리미엄` · `국산` · `26년`
- 다른 곳의 연관 · 자동완성: `밤 삶는 방법` · `밤 영어로` · `밤 그림` · `밤까는기계` · `보늬밤`
- 연관의 연관: `묘목시장` · `장미묘목` · `쌀20KG` · `에어프라이어`

이것들은 네이버 공식 API 에 없다. 쇼핑 상품 목록(쇼핑검색 API 는 7/31 종료)과 장터들의 자동완성을 긁어야 나오는데 그건 하지 않는다(docs/04 · 08),
긁는다 해도 저쪽이 쌓아 둔 목록과 같아진다는 보장이 없다. **같은 목록을 얻는 길은 아이템스카우트가 준 목록을 쓰는 것 하나다.**

330개 전부 네이버 키워드도구에 정확히 같은 키워드로 있다(대조 330/330). 그래서 목록만 있으면 숫자는 네이버 지금 값으로 다 채울 수 있다.

## 그래서 이렇게 했다

1. **씨앗의 엑셀이 있으면 그 목록 그대로를 먼저 보여준다.** `넣는곳\아이템스카우트` 에 둔 `밤_키워드_itemscout_related_keywords_….xlsx` → 씨앗 `밤`.
   키워드 · 개수 · 순서가 같다. 표시줄에 `아이템스카우트와 같은 목록` 이라고 적고, 옆 단추로 키워드랩 확장 목록(네이버 연관 + 수집본)과 오간다.
2. **숫자는 네이버 지금 값이다.** 아이템스카우트 연관키워드의 검색수 · 클릭은 낡은 저장값이라(docs/16) 쓰지 않는다. 엑셀에서는 목록 · 상품수 · 카테고리 · 분류만 받는다.
3. **저장된 화면(claude.ai)에도 싣는다.** `build-islist.mjs` 가 PC 에 저장된 목록(`naver-out/uploads`)의 키워드마다 네이버 값을 받아 `app/data-is.js` 로 쓴다
   (실시간 서버를 켜 둔 채 실행). 화면은 이것을 읽어 엑셀을 올린 것과 똑같이 처리한다.
4. **엑셀이 없는 씨앗은 "아이템스카우트 목록 없음" 이라고 밝힌다.** 같은 목록인 척하지 않는다. 엑셀을 받아 넣는곳에 두면 그 목록으로 바뀐다고 안내한다.

검증 (저장된 화면 · PC 실시간 양쪽): `밤` → 330개 · 빠진 것 0 · 더한 것 0 · 순서 같음. `과일꾼`(9/17 엑셀) → 99개.

## 지켜야 할 것

- `data-is.js` 에는 아이템스카우트에서 받은 자료(목록 · 상품수 · 카테고리)가 들어 있다. **공개 저장소에 올리지 않는다** — 저장소에는 빈 파일(`window.ISRECS=[];`)만 두고,
  진짜 파일은 수집기 `app\` 와 아티팩트에만 둔다. 아티팩트도 보갬만 보는 비공개로 둔다.
- 엑셀은 보갬이 보는 품목만 직접 받는다. 전 키워드를 대량으로 받는 일은 하지 않는다(약관 10 · 11 · 17조, 10/11 합의).
  그래서 **"모든 씨앗이 아이템스카우트와 같다" 는 되지 않는다. 엑셀을 넣은 씨앗만 같다.**
- 새 엑셀을 넣은 뒤 저장된 화면에도 반영하려면 `build-islist.mjs` 를 다시 돌리고 아티팩트를 다시 올려야 한다(로드가 한다).
