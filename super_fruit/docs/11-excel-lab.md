# 엑셀 분석 탭

2026-10-09. 보갬: "정책도 바뀌고 공급사까지 하는 것은 일단 무리일 수 있어서,
차라리 내가 계산기랑 공급가 비교표를 엑셀로 만든 걸 첨부할 테니까
이런 기능이 사이트에 그냥 있어서 엑셀로 넣으면 데이터가 편하게 보이고
비교 가능한 그래프도 있게 구현하면 좋을 것 같아."

맞는 판단이다. 공급사 20곳 API 를 쫓아다니는 것보다 훨씬 빠르다.
23단계(open API)는 그대로 두되 이쪽을 주 통로로 한다.

## 끌어다 놓으면 끝

브라우저 안에서 전부 읽는다. 파일은 어디로도 올라가지 않는다.
bat 도 팩도 왕복도 없다.

xlsx 는 zip 이라 `DecompressionStream("deflate-raw")` 로 풀고 XML 두 개만 꺼낸다.
외부 라이브러리를 하나도 안 쓴다 — CDN 이 막혀도 돌아간다.

## 장부 두 가지를 스스로 가려낸다

| 장부 | 알아보는 단서 | 읽는 열 |
|---|---|---|
| 공급가 비교표 | `전체상세` 시트 · 거래처 · 공급가 · 중량kg | 거래처 · 상품명 · 옵션명 · 품종구분 · 중량kg · 과수최소/최대 · 공급가 · 배송비포함원가 · 판매상태 · 확인필요사항 |
| 판매가 계산기 | `요약` 시트 · 공헌이익 · 이익률 | 옵션명 · 총원가 · 네이버 판매가/공헌이익/이익률/최소ROAS · 쿠팡 등록가/공헌이익/이익률 · 판정 |

계산기를 **먼저** 묻는다. 계산기의 `설정_원가` 탭에도 거래처와 "원 공급가" 가 있어서
공급가표로 오인됐다. 공헌이익은 계산기에만 있는 열이라 그것을 기준으로 삼는다.

## 실제 파일에서 잡은 파서 결함 셋

보갬이 올린 두 파일은 엑셀이 아니라 라이브러리가 쓴 것이라, 내 파서의 가정이 줄줄이 깨졌다.

**1. 네임스페이스 접두사.** `<si>` 가 아니라 `<x:si>` 였다. 시트 목록이 통째로 비었다.
`(?:\w+:)?` 로 흘린다.

**2. 속성 순서.** rels 가 `Target` 을 `Id` 보다 먼저 쓴다.
`Id="..."[^>]*Target="..."` 가 안 맞았다. 속성을 따로 뽑는다.

**3. 자기닫힘 셀 — 이게 제일 고약했다.**
```
<x:c r="E2" s="74" t="str" />
```
`<c\b([^>]*)(?:\/>|>…<\/c>)` 에서 `[^>]*` 가 욕심내어 끝의 슬래시까지 삼키고,
`>` 로 닫힌 것으로 본 뒤 **다음 셀의 `</x:c>`** 를 자기 것으로 썼다.
그 줄 전체가 한 칸씩 밀린다. 중량이 품위 자리에 들어가 `중량kg` 이 전부 비었다.
`[^>]*?` 로 게으르게 바꿔 고쳤다.

같은 결함이 `parse-supply.mjs` 와 `import-itemscout.mjs` 에도 있었다. 셋 다 고쳤다.

**4. FileList 는 살아있는 목록이다.**
```js
inp.onchange = function(){ take(inp.files); inp.value=""; };
```
`take` 가 `await` 로 멈춰 있는 사이 `inp.value=""` 가 돌면 목록이 그 자리에서 비워진다.
두 파일을 한꺼번에 떨구면 두 번째가 조용히 사라졌다. 오류도 안 난다.
먼저 배열로 떠두고 쓴다.

## 차트

`dataviz` 스킬의 절차를 따랐다. 형태 → 색의 역할 → **검증기 실행** → 마크 → 호버 → 접근성 → 눈으로 확인.

팔레트는 `validate_palette.js` 로 라이트·다크 양쪽 통과.
라이트에서 초록·노랑이 3:1 아래라 WARN 이 뜨는데, 검증기 규칙대로
**직접 라벨 + 전체 표**를 함께 둬서 색만으로 식별하지 않게 했다.

| 차트 | 형태를 고른 이유 |
|---|---|
| 중량별 원/kg | 공급처를 구분하는 일 = categorical. 품종마다 따로 그린다 |
| 규격별 최저가 대비 추가 비용 | 기준값과의 차이 = 참조선에서 뻗는 막대 |
| 옵션별 공헌이익 네이버 vs 쿠팡 | 항목마다 전·후 두 점 = 덤벨, 한 색조 두 농도 |
| 옵션별 이익률 | 기준 20% 대비 = 상태색 둘 + 점선 기준선 |

### 눈으로 보고 고친 것

**눈금이 44,064 / 33,048 이었다.** 최대값을 그대로 넷으로 나눠서.
`niceMax()` 로 1·2·2.5·5·10 배수로 올린다.

**직접 라벨이 오른쪽으로 잘리고 서로 겹쳤다.** 여백을 132px 로 늘리고,
y 가 13px 안에 들면 아래로 밀어낸다.

**품종이 섞여 눈금이 망가졌다.** 깐옥광밤 40,800원/kg 과 옥광밤 13,500원/kg 이
한 축을 쓰면서 아래쪽 선 넷이 서로 붙어 읽을 수 없었다. 품종마다 나눠 그린다.
색은 공급처에 붙어 있어 facet 을 건너도 같은 색이다.

**막대가 전부 꽉 찼다.** 13,500 대 14,600 은 92% 대 100% 라 눈으로 구분이 안 된다.
공급가 자체가 아니라 **최저가 대비 추가 비용**을 그리도록 바꿨다.
제일 싼 곳은 초록 점, 나머지는 더 내는 만큼만 주황 막대.
```
옥광밤 4kg · 최저 39,800원 (최고집)
  행운프레시 대 4kg        +3,400원 ·  9%
  신선천재김사장 대 4kg     +7,900원 · 20%
  하루팜 대과 4kg         +20,200원 · 51%
```

## 아직 안 된 것

- **등급이 비어 있는 줄이 많다.** 보갬 시트의 `크기등급` 이 대부분 비어서
  한 공급사의 중/대가 같은 묶음에 들어간다. 묶음은 품종+중량까지만 하고
  등급은 줄 라벨의 옵션명으로 읽게 뒀다.
- **과수 미표기 18/18.** g/과 를 못 낸다. 공급사가 안 적어준 것이라
  이 화면에서 할 수 있는 일이 없다. 표의 "확인 필요" 열에 그대로 남겨뒀다.
- 다른 모양의 엑셀은 아직 모른다. 못 알아보면 시트 이름을 화면에 찍어준다.
