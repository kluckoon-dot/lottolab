# 슈퍼프룻 — 무기 설계서

2026-09-10 · 용도 확정: **본인 전용 비공개 도구**

---

## 한 문장 정의

> **"이거 팔릴까"가 아니라 "이거 남을까"에 답하고, 그 답에 판정을 달아주는 도구.**

아이템스카우트·판다랭크는 숫자를 보여주고 **판단은 사용자에게 떠넘긴다.**
슈퍼프룻은 판단까지 한다. 그게 무기의 정의다.

---

## 무기가 되는 건 데이터가 아니다

냉정하게 보자. 데이터만 놓고 겨루면 형이 진다.

- 아이템스카우트는 전 카테고리를 훑고, 슈퍼프룻은 농산물만 본다
- 걔들은 크롤링으로 상품수·순위·판매량 추정까지 만든다. 형은 안 한다
- 걔들은 전담 팀이 있고, 형은 혼자다

**데이터 양으로는 절대 못 이긴다. 이길 필요도 없다.**
무기는 다른 세 곳에서 나온다.

### 무기 ① 판정 엔진 — 남이 못 베끼는 유일한 것

형은 이미 자기 판단 체계가 있다. **린정 / 반린정 / 패스.**
이건 데이터가 아니라 **형의 장사 경험이 압축된 규칙**이다. 이걸 코드로 박는 게 핵심이다.

아이템스카우트가 이걸 못 하는 이유는 기술이 없어서가 아니다.
**남의 판단 기준을 대신 정해줄 수 없어서다.** 사용자마다 마진 기준도, 리스크 감내도 다르니까.
형은 사용자가 한 명이라 그게 가능하다. **1인용이라는 게 약점이 아니라 무기다.**

### 무기 ② 시즌 타이밍 — 농산물에서 이게 전부다

농산물은 "뭘 파느냐"보다 **"언제 들어가느냐"**가 마진을 결정한다.
아이템스카우트는 시즌성을 **지표로만** 준다. "지금 들어가라 / 지금 빠져라"는 안 말해준다.

검색어트렌드 3년치가 있으면 품목별 시즌 곡선을 그릴 수 있다. 거기서
**진입 구간 / 피크 / 철수 구간**을 계산해서 알림으로 뽑는 게 농산물 특화 무기다.

### 무기 ③ 피드백 루프 — 시간이 갈수록 벌어지는 해자

**아이템스카우트는 형이 뭘 샀고 얼마 남겼는지 모른다. 슈퍼프룻만 안다.**

판정을 내렸으면 결과를 기록한다. 린정 준 품목이 실제로 남았나?
1년 쌓이면 판정 규칙을 실적으로 교정할 수 있다.
**이건 데이터를 많이 가진 쪽이 아니라 자기 거래를 기록한 쪽만 가질 수 있다.**

## 판정 엔진 설계

### 입력 4축

| 축 | 지표 | 소스 |
|---|---|---|
| **수요** | 월 검색수(PC/MO), 월평균 클릭수, CTR | 검색광고 API |
| **경쟁** | 광고 깊이, 1~3위 예상 입찰가 | 검색광고 API |
| **마진** | 공급가, 도매 시세, 예상 판매가 | 온그린 + KAMIS |
| **시즌** | 3년 검색 추세상 현재 위치 | 검색어트렌드 |

> **솔직하게 짚을 것:** 상품수·경쟁강도 원본이 없다(쇼핑검색 API 종료).
> 그래서 경쟁은 **광고 깊이와 입찰가로 대리 측정**한다.
> 광고가 깊고 입찰가가 높으면 경쟁이 세다고 보는 것 — 논리는 맞지만 **완벽한 대체는 아니다.**
> 화면에 반드시 "광고 기반 추정"이라고 표시할 것. 원본인 척하지 말 것.

### 판정 규칙 (초안 — 형이 숫자를 채워야 함)

```
린정      마진율 ≥ 25%  AND  월 검색수 ≥ 10,000  AND  시즌 진입 구간
반린정    셋 중 둘 충족  →  못 채운 하나를 반드시 문장으로 명시
패스      마진율 < 15%  OR  시즌 철수 구간
```

**이 숫자는 내가 정할 수 없다. 형 장사 기준이다.**
처음엔 대충 넣고, 피드백 루프로 6개월 뒤에 교정하는 게 맞다.

### 출력 — 이게 화면의 전부다

```
┌────────────────────────────────────────────────┐
│  샤인머스캣 2kg                        린정     │
├────────────────────────────────────────────────┤
│  수요   월 검색 41,200  (PC 8,400 / MO 32,800) │
│         3주 연속 상승                           │
│  시즌   진입 3주차 · 피크까지 5주               │
│  마진   공급가 18,500 → 판매가 29,900          │
│         마진율 28.4%                            │
│  시세   KAMIS 도매 12,400원/kg                  │
│         공급가 프리미엄 +19%                    │
├────────────────────────────────────────────────┤
│  왜 린정                                        │
│  시즌 진입 초기 + 마진 25% 상회                 │
│  + 검색 3주 연속 상승                           │
│                                                 │
│  주의                                           │
│  도매 대비 공급가 프리미엄이 높다.              │
│  다른 공급사 견적 1개 더 받아라.                │
├────────────────────────────────────────────────┤
│  경쟁 지표는 광고 기반 추정입니다               │
│  KAMIS 2026-09-09 조사 · 공급가 2026-09-10      │
└────────────────────────────────────────────────┘
```

**판정 옆에 반드시 "왜"와 "주의"가 붙는다.** 이게 규칙이다.
장점만 나열하고 끝내는 카드는 만들지 않는다. 린정에도 주의가 붙어야 한다.

---

## 화면 3개. 그 이상 만들지 마라

**① 오늘의 판정** — 진입 시점에 들어온 품목 몇 개. 카드 형태.
아침에 열어서 3분 보고 닫는 화면. 여기가 메인이다.

**② 품목 상세** — 카드 하나를 파고든 화면. 4축 차트, 공급사별 견적 비교, 시즌 곡선.

**③ 판정 기록** — 내린 판정과 실제 결과. 피드백 루프의 입력창.
"린정 줬는데 실제로 남았나"를 여기서 기록한다.

지금 대시보드는 화면이 많다. **무기는 화면이 적을수록 날카롭다.**

## 기존 자산 재활용 맵

이미 만든 게 많다. 버릴 필요 없다.

| 기존 자산 | 무기에서의 역할 |
|---|---|
| 검색광고 지표 수집기 | **수요·경쟁 축 그대로 사용** |
| 검색어트렌드 3년 추세 | **시즌 축의 원본** |
| 탑다운 품목 탐색 | 후보 발굴 (판정 대상 큐) |
| 공급사 견적 저장 API | **마진 축의 절반** |
| NAVER 원본 / 승인값 배지 | 소스 표기 체계 — 소스 늘수록 더 중요 |
| 쇼핑인사이트 기기·성별·연령 | 상세 화면 보조 지표 |

**새로 필요한 것은 셋뿐이다.**
1. KAMIS 연동 (마진 축의 나머지 절반)
2. 판정 엔진 (규칙 + 카드 렌더링)
3. 판정 기록 테이블 (피드백 루프)

---

## 로드맵

| 단계 | 할 일 | 왜 |
|:--:|---|---|
| **0** | 카테고리 ID 버그 수정 | 안 고치면 쌓는 게 다 무효 |
| **1** | KAMIS 연동 + 품목 매칭률 확인 | 마진 축 완성. 매칭률 보고 규모 결정 |
| **2** | **판정 엔진 v1** — 규칙 하드코딩, 카드 1종 | 여기서 무기가 된다 |
| **3** | 온그린 키 발급 → 공급가 실연동 | 마진이 실시간이 된다 |
| **4** | 시즌 곡선 + 진입/철수 알림 | 농산물 특화 완성 |
| **5** | 판정 기록 테이블 | 해자가 자라기 시작 |
| **6** | API 허브 키 교체 | 2027-06-30 데드라인 |
| **7** | 6개월 뒤 규칙 교정 | 실적 기반 |

**2단계가 제일 중요하다.** 데이터가 완벽하지 않아도 판정 엔진부터 붙여라.
불완전한 데이터로 내린 판정이, 완벽한 데이터로 안 내린 판정보다 낫다.
틀리면 3단계에서 고치면 된다.

## 버릴 것 — 다시 확인

- **크롤링.** 상품수·순위·판매량 추정·리뷰 분석. 전부 포기한다.
  본인 전용이라도 DB권 침해는 성립한다. 리스크 대비 가치가 없다.
- **ItemScout 동일성.** 원천이 다르다. 같아질 수 없고, 같을 필요도 없다.
- **화면 늘리기.** 지표를 하나 더 붙이고 싶을 때마다
  "이게 판정을 바꾸나?"를 물어라. 안 바꾸면 안 붙인다.
- **전 키워드 커버리지.** 4,041개 다 볼 필요 없다.
  형이 실제로 취급할 **20~30품목**이면 충분하다. 좁을수록 날카롭다.

## 이 설계의 약점 — 미리 밝힌다

숨기면 나중에 배신당한다. 세 개다.

**① 경쟁 측정이 대리 지표다.**
상품수 원본이 없어 광고 깊이·입찰가로 대신한다. 광고를 안 도는 시장은 과소평가된다.
→ 상세 화면에서 눈으로 보완할 것.

**② KAMIS 커버리지가 좁을 수 있다.**
도매 69품목 116품종. 샤인머스캣이 품종으로 안 잡히면 마진 축 정밀도가 떨어진다.
→ 1단계에서 확인하고, 안 되면 공급가 단독으로 마진을 계산한다.

**③ 판정 규칙 초기값에 근거가 없다.**
마진율 25%, 검색수 10,000은 내가 임의로 넣은 숫자다.
→ 형 실제 거래 기준으로 바꿔라. 그리고 6개월 뒤 실적으로 교정해라.
**이 약점은 피드백 루프가 시간이 지나며 스스로 메운다. 그래서 5단계가 중요하다.**

## 원칙 — 키워드에는 옳고 그름이 없다

2026-09-11 추가. 실데이터를 받고 확인된 규칙이다.

```
샤인머스캣   월 검색   8,710
샤인머스켓   월 검색  78,600
```

맞춤법은 "머스캣"이 맞다. 그런데 사람은 "머스켓"으로 검색한다.
**이건 오타가 아니라 별개의 시장이다.** 둘 다 상품을 팔 수 있고, 입찰가도 경쟁도도 따로 움직인다.

그래서 이 시스템에는 금지 사항이 셋 있다.

| 하지 않는다 | 왜 |
|---|---|
| 철자가 비슷하다고 합치기 | 시장이 다르다. 합치면 한쪽을 잃는다 |
| 검색량 큰 쪽을 대표값으로 삼기 | 작은 쪽이 경쟁이 약해 오히려 황금키워드일 수 있다 |
| 검색량이 적다고 지표 수집 건너뛰기 | 롱테일이 마진의 원천이다 |

**모든 키워드는 예외 없이 같은 대접을 받는다.**
월검색수 · 클릭수 · CTR · 경쟁도 · 1~3위 입찰가(PC/모바일) · 3년 주간 추세 · 연령 · 성별 · 기기.
검색량이 `< 10`으로 가려진 키워드도 버리지 않고 담되 가려진 값이었음을 표시한다.

### 화면에 미치는 영향

- 키워드는 품종에 종속되지 않는다. **키워드 자체가 1급 단위**다
- 검색창은 전체 키워드를 대상으로 한다. 품종을 몰라도 키워드로 찾을 수 있어야 한다
- 상세 화면은 어떤 키워드로 들어와도 동일하게 열린다
- 한 키워드가 여러 품종에서 발견되면 그 목록을 모두 보여준다. 하나를 골라 대표로 삼지 않는다

### 수집기에서 지킨 방법

- 중복 판단은 **키워드 문자열 완전 일치**로만 한다. 유사도로 묶지 않는다
- 같은 키워드가 여러 힌트에서 나오면 힌트 목록을 누적한다. 값이 다르면 `seenAlso`에 기록만 하고 덮지 않는다
- 입찰가 수집에 **검색량 하한이 없다**. 전부 받는다
- 분량이 많아지므로 중간 저장과 이어하기로 감당한다. 버리는 방식으로 줄이지 않는다
