# 실시간 조회 — 숫자가 달랐던 진짜 이유

2026-10-09. 보갬: "아이템스카우트에서 사용하는 키워드와 슈퍼프룻 키워드의 수치가 너무 다르고
네이버 광고의 도구에 있는 키워드랑 비교해도 모두 달라. 아이템스카우트와 네이버는
수치가 동일한 것으로 보아서 아이템스카우트는 정확하게 수집하는 것 같아."

## 원인 — 계산이 아니라 날짜

청도반시를 열어봤다.
```
우리 화면       1,180회   (PC 320 · 모바일 860)
수집 시각       2026-09-14 (추세 마지막 주)
그 주 상대지수   1~3 / 100   ← 1년 중 바닥
작년 같은 철     81 / 100    ← 바닥의 30배 가까이
오늘            2026-10-09  ← 성수기 한가운데
```

검색광고 API 의 검색수는 **"최근 30일"** 이다. 우리 화면은 9월 14일에 한 번 찍은 사진이었고,
아이템스카우트와 네이버 키워드도구는 **지금** 값을 보여준다. 둘이 서로 같고 우리만 다른 이유다.

9월 수집 직후 아이템스카우트와 대조했을 때는 차이 중앙값 −2.5% 였다(09 문서).
그때는 맞았다. 한 달이 지나며 제철 품목부터 어긋났다.

## 해결 — 키가 있는 PC 에서 바로 부른다

네이버 검색광고 API 는 비밀키 서명이 필요하다. 공개 페이지(claude.ai)에 키를 넣을 수 없고,
그 페이지는 CSP 때문에 외부 주소로 요청도 못 보낸다. 그래서 **보갬 PC 에 작은 서버**를 띄운다.

```
0-keyword-lab.bat → node live-server.mjs --open → http://127.0.0.1:8787
```

| 경로 | 하는 일 |
|---|---|
| `GET /api/live?kw=` | `/keywordstool` (검색수·클릭수·클릭률·광고깊이·경쟁도 + **연관키워드 전부**) 와 `/estimate/average-position-bid/keyword` (검색어 + 연관 상위 29개, PC·모바일 1~3위) |
| `GET/POST/DELETE /api/uploads` | 엑셀 분석 결과를 `naver-out/uploads/` 에 저장·목록·삭제 |
| 그 밖 | `keyword-lab.html` · `xlsx-lab.js` · `data-*.js` 만 내준다 |

`/keywordstool` 응답이 곧 아이템스카우트의 "연관 키워드" 탭과 같은 출처다.

같은 키워드는 3시간 캐시. 화면의 ↻ 로 강제로 새로 받는다.

### 안전

- `127.0.0.1` 에만 붙는다. 같은 와이파이의 다른 기기도 못 들어온다.
- 내주는 파일을 정규식으로 제한했다. `key.txt` → 404, `..%2Fkey.txt` → 404 확인.
- 응답·오류 문구에서 키 값을 가린다.

## 화면에 붙이는 법 — 덮어쓰고 덧붙인다

실시간 결과를 별도 패널로 따로 그리면 황금점수·판정·상세·마진이 전부 다시 만들어져야 한다.
대신 **기존 행에 덮어쓰고, 없는 키워드는 덧붙인다**. 그러면 모든 탭이 새 숫자로 그대로 돈다.

타입드 배열은 늘어나지 않으므로 `CAP = N + 60000` 칸을 미리 잡았다.
한 줄 계산을 `statRow(i)` · `groupRow(i)` 로 빼서 덧붙인 줄만 다시 계산한다.
새 키워드의 의도는 팩커와 같은 다섯 칸 규칙으로 화면에서 매긴다.

`한 달 검색수` 카드가 출처를 말한다.
```
실시간 05:21           네이버 최근 30일 · 방금 받음
9월 수집본 · 낡음       9월 14일 기준. 제철 품목은 지금과 크게 다를 수 있다
```

## 엑셀은 저장된다

| 연 곳 | 저장 위치 |
|---|---|
| 실시간 서버 (127.0.0.1) | 그 PC 의 `naver-out/uploads/<id>.json` |
| claude.ai | 그 브라우저의 localStorage |

같은 파일을 다시 올리면 덮어쓴다(id = 파일명 + 종류).
새로고침 뒤에도 남고, 지우기는 디스크에서도 지운다. 브라우저로 확인했다.

## 검증과 한계

가짜 네이버 서버(서명 검사 포함)로 확인했다.
```
ping → 키 확인 · 조회 → exact + 연관 3 + 입찰가 PC/모바일 1~3위
같은 키워드 다시 → 캐시 · fresh=1 → 다시 부름
"< 10" → 숫자 10 + 가림 표시
업로드 저장 → 새로고침 뒤 유지 → 삭제 시 디스크에서도 사라짐
key.txt · 경로 탈출 → 404
```

**실제 네이버와의 대조는 아직이다.** 이 컨테이너에는 키도 네이버 접근도 없다.
첫 검색 하나를 네이버 키워드도구와 나란히 놓고 숫자가 같은지 보는 것이 진짜 검증이다.
같은 API 를 같은 방식으로 부르므로 같아야 한다 — 다르면 그게 버그다.

## 서버 없이 갱신 — 네이버 키워드도구 엑셀

searchad.naver.com → 도구 → 키워드도구 → 다운로드한 엑셀(`연관키워드_20261009_1428.xlsx`)을
엑셀 분석 탭에 떨구면 그 키워드들의 숫자가 그 시점 값으로 바뀐다. claude.ai 에서도 된다.

- 알아보는 법: 헤더 `연관키워드` + 둘째 줄 `월간검색수(PC)/(모바일)`. 공급가표·계산기보다 먼저 검사한다.
- 기준 시각: 파일 이름의 `YYYYMMDD_HHMM`. 없으면 올린 시각.
- `< 10` → 0 + 가림 표시, `-` → 0.
- 덮어쓰기 전 9월 값을 떠서 같이 저장 → "9월 → 지금" 표와 배수.
- 저장되고, 새로고침하면 오래된 파일부터 다시 적용한다(새것이 이긴다).
- 숫자 옆 출처: `키워드도구 10/9 14:28`. 위쪽 도장: `9월 수집본 + 키워드도구 77개 10/9 갱신`.
- 입찰가 1~3위는 이 엑셀에 없다. 입찰가는 실시간 서버로만 새로 받는다.

10월 9일 14:28 파일(77개)로 확인한 것:
```
9월 수집본과 대조 57개 · 중앙값 3.4배 · 2배 이상 45개(79%) · 새 키워드 20개
청도반시   1,180 → 13,470  ×11.4  (아이템스카우트 13,470 과 같다)
대봉단감      40 →    460  ×11.5
단감가격      80 →    720  ×9.0
```
숫자가 달랐던 건 계산이 아니라 날짜였다. 다시 확인됐다.

한 가지 더: 페이지에 `<meta charset="utf-8">` 를 넣었다. 파일을 직접 열거나
charset 을 안 주는 서버에서 열면 한글 정규식이 깨져 엑셀을 못 알아봤다.
