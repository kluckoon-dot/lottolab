## 상품수 — 결론

공식 경로는 이번에도 없다.
- 쇼핑 검색 API: 2026-07-31 종료, API HUB 콘솔 목록에 없음 (09 문서에서 우리 키로 404 확인)
- 아이템스카우트 · 블랙키위: 공개 API 확인 안 됨
- 네이버쇼핑 검색 결과를 프로그램으로 긁는 것: 하지 않는다 (DB권 판례 · docs/04). 아이템스카우트 사이트를 자동으로 도는 것도 같다

남은 길 둘, 둘 다 사람이 본 숫자다.
1. **아이템스카우트 연관키워드 엑셀** — 한 번에 100~132줄. 엑셀 분석 탭에 떨구면 상품수·경쟁강도·대표 카테고리가 붙고 날짜별로 쌓인다.
2. **키워드별 직접 입력** — 상품수 카드에 "네이버쇼핑에서 상품수 보기 ↗" 와 입력칸. 넣으면 경쟁강도 = 상품수 ÷ 그때 검색수로 바로 계산, 이 브라우저에 남는다.

판정(린정·반린정·패스)에는 상품수를 쓰지 않는다. 있으면 보여주고 거를 수 있게만 한다.
그래서 상품수가 비어도 화면은 온전히 돈다 — "포기" 가 아니라 "선택" 으로 둔다.

## 덤으로 잡은 것

- **pack-data 가 최신값 층을 조용히 버렸다.** 9월 값 보존 코드가 아래에서 정의되는 `num` 을 먼저 불러 예외가 났고,
  `catch {}` 가 그걸 "fresh.json 없음" 으로 삼켰다. 화면 데이터가 9월 값으로 나갈 뻔했다.
  이제 파일이 없는 것(ENOENT)과 읽다 터진 것을 가르고, 터지면 멈춘다.
- **9월 주간 추세의 눈금.** 실시간 서버 없이 볼 때 9월 추세(9/14 끝)를 오늘 검색수에 맞추면 9월 바닥이 10월 성수기 값으로 부풀어
  곡선이 몇 배가 된다(청도반시 약 11배). 9월 값을 26번 열 `sepTot` 으로 남겨 그걸로 맞춘다.
- **휴대폰에서 데스크톱 폭.** 실시간 서버가 내주는 페이지에 viewport 줄이 없었다(claude.ai 는 자동으로 붙여서 안 보였다). 넣었다.
- **판정 기록 탭.** 판정 그때의 숫자·설정을 떠두고, 나중에 남음/본전/손해·매출·광고비·주문수를 적는다.
  린정·반린정·패스별 "실제로 남은 비율" 을 센다 — docs/05 무기 ③ 피드백 루프. 이 PC 의 `naver-out/verdict-log.json`.
